# Proposed I2C breakout additions

Research date: **23 October 2026**. Status: **implemented as product-reference records** in [working_oomp_populate_i2c.py](../../working_oomp_populate_i2c.py). All 29 named manufacturer boards (28 I2C-capable plus analog ADXL335) have been generated in `parts_source` and then `parts`. AliExpress candidates remain deferred. See [generation and evidence notes](../../I2C_BREAKOUTS.md).

I recommend **28 I2C-capable manufacturer boards**: the original **16 first-batch boards**, **six follow-up boards**, and **six classic accelerometer carriers** added below. There is also **one optional analog accelerometer**, outside the I2C total. This covers everyday measurement, control, displays and bus expansion before multiplying similar carrier variants. Product selection is editorial: familiarity, practical coverage, software support and available board documentation. It is not a measured sales-popularity ranking.

Research used the **Codex in-app browser** to search SparkFun and Adafruit and inspect the linked product descriptions, specifications and revision notes. AliExpress access was initially rejected by the browser's site-safety policy. After the user enabled the site and confirmed that it loaded manually, both a fresh navigation and an attempt to read the user's existing in-app tab were still rejected for agent access before page content could be read. Manual page loading therefore does not establish agent access. The AliExpress section remains an unverified search queue; no particular sellers, prices, sales counts or item IDs are asserted.

## Taxonomy and record structure

The existing non-microcontroller population code starts at `electronic / breakout`, appends `type_1` through `type_4`, then the board description, and uses slots 14/15 for manufacturer/product number. Microcontroller definitions already use fixed variant and geometry slots. The explorer supports 15 taxonomy fields and builds IDs from populated fields. Relevant local sources:

- [Population and taxonomy assembly](../../working_oomp_populate.py)
- [Existing output board example](../../working_oomp_populate_output.py)
- [Existing power board example](../../working_oomp_populate_power.py)
- [Microcontroller fixed-slot example](../../working_oomp_populate_microcontroller_rp2040.py)
- [Explorer ID builder](../../webserver/services/taxonomy_builder.py)

For these new definitions I propose the following fixed slots, while leaving existing records intact:

| Field | Proposed meaning | BME280 example |
| --- | --- | --- |
| `taxonomy_1` | Domain | `electronic` |
| `taxonomy_2` | Item kind | `breakout` |
| `taxonomy_3` / `type_1` | Main functional branch | `sensor` |
| `taxonomy_4` / `type_2` | Functional group | `environmental` |
| `taxonomy_5` / `type_3` | Measurement or role | `temperature_humidity_pressure` |
| `taxonomy_6` / `type_4` | Device or board family | `bme280` |
| `taxonomy_7` | Physical/electrical assembly variant | e.g. `qwiic_without_headers`, after confirming the supplied assembly |
| `taxonomy_8` | Verified board dimensions | e.g. `<width>_mm_width_<height>_mm_height`; unresolved at this proposal stage |
| `taxonomy_9`–`taxonomy_13` | Reserved | Empty |
| `taxonomy_14` | Board manufacturer | `sparkfun` |
| `taxonomy_15` | Manufacturer product number | `sen_15440` |

The manufacturer and part-number slots are mandatory positions for every eventual board definition. Unresolved AliExpress item IDs stay unknown rather than becoming invented part numbers. Manufacturer names and product numbers are normalized for IDs (for example vendor SEN-09836 becomes `sen_09836`), while the original vendor spelling is retained as source metadata.

The FRAM entry deliberately leaves `taxonomy_6` empty until the fitted chip is established. Fixed positions stop a missing family value from shifting the assembly or dimensions. Values shown as examples/placeholders are not ready-to-generate IDs.

I2C should be a cross-cutting filter such as proposed `interfaces: [i2c, spi]`, not the top-level home for every board. Only bus-infrastructure products belong under `interface / i2c`. Suggested additional metadata includes `i2c.default_address_7bit`, address options and selection method, board supply range, logic levels, pull-up rail/value/disconnect method, clock/clock-stretching requirements, connector/contact identities and software support. These are proposed fields, not a claim that the current catalogue already implements them. Multi-device boards need per-device I2C records.

A passive Qwiic hub would be a connector/accessory record. It must not be conflated with a TCA9548A multiplexer. Likewise, standalone analog amplifiers, SPI-only converters and bare rotary encoders should not enter this list simply because a store search returns them.

The top-level population script now loads the dedicated peripheral populate file and preserves its `breakout_function_v1` fixed taxonomy alongside the microcontroller definitions. Manufacturer remains in slot 14 and part number in slot 15. Running `python working_oomp_populate_i2c.py --parts` regenerates these source records and only their corresponding parts records.

## Remaining evidence for mechanical and electrical coverage

The product pages establish the candidates and functions. They do not yet constitute a complete mechanical or electrical import.

1. Retain product identity, selected assembly and PCB revision, source URLs, retrieval date and local schematic/CAD/drawing references with checksums.
2. Establish PCB outline, hole diameters and centred XY coordinates, component/connector envelope and clearance. Keep product dimensions separate from a verified carrier outline; no inferred hole coordinates from photographs.
3. Record each physical connector and pad, signal name, supply/logic restrictions, address controls and extra signals such as IRQ, XSHUT, RESET or OE.
4. Preserve evidence status and unknowns. Separate board variants when mounting, pin order, components or assembly differ. Do not copy a branded carrier's geometry or voltage tolerance to a generic module with the same chip.
5. The definitions now exist with explicit evidence gaps. Enable mounting-plate and pinout-drawing generation only after the corresponding geometry is verified; review software/host compatibility separately from catalogue inclusion.

Several pages explicitly document mechanical changes: [ADS1115](https://www.adafruit.com/product/1085) changed shape/pinout with the QT revision; [INA219](https://www.adafruit.com/product/904) changed mechanical shape and can contain different INA219 grades/packages; [OLED 938](https://www.adafruit.com/product/938) changed layout, holes and default interface. These are concrete reasons for revision-aware records.

Stock is a dated observation, not a condition for catalogue inclusion: SparkFun [TMP117](https://www.sparkfun.com/sparkfun-high-precision-temperature-sensor-tmp117-qwiic.html) and [NAU7802](https://www.sparkfun.com/sparkfun-qwiic-scale-nau7802.html) showed backorder, and Adafruit [PCA9685](https://www.adafruit.com/product/815) showed out of stock during this research. No purchasing is proposed or performed.
